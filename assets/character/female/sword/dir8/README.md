# Диагональные направления персонажа

Паки от художника нарисованы на четыре стороны. Здесь лежат исходники
двух дорисованных диагоналей — `se` (down_right) и `ne` (up_right).
Ещё две, down_left и up_left, получаются отражением и своих файлов не
имеют. Такой каталог есть у каждого пака в `assets/character/*/*/dir8`.

## Как это устроено

Спрайт лежит текстом: один символ — один пиксель, файл — один слой
кадра. Правка адресуется конкретной клеткой, и весь спрайт виден в
диффе. Строка `@ x y` задаёт левый верхний угол окна в координатах
кадра 64x64, строки с `#` — комментарии, точка — прозрачно.

Раскладка: `dir8/<клип>/<se|ne>/`. Слои рисуются в том же порядке, что
и `parts` исходного пака:

| файл | что |
| --- | --- |
| `shadow.txt` | тень на земле; одна на клип, не качается с телом |
| `body<N>.txt` | корпус и ноги, по кадру на файл |
| `sword.txt` | оружие, если оно не машет: одна форма плюс сдвиги |
| `sword<N>.txt` | оружие, если машет (атаки): своя форма на кадр |
| `head.txt` | голова, нарисованная вручную; одна на направление |
| `head<N>.txt` | голова на конкретный кадр, если общая не годится |
| `swing<N>.txt` | росчерк замаха, поверх всего |
| `red<N>.txt` | вспышка попадания, полупрозрачная плёнка |
| `poses.txt` | покадровые сдвиги головы и оружия |

Головы нарисованы вручную только две на пак — фронтальная три четверти
и вид со спины. Остальное снято с готовых направлений трассировщиком.
Исключения: в смерти голова лежит лицом вниз, а в уроне зажмурена —
там стоит `head<N>.txt` из оригинала и своя `head.txt` с сомкнутым
веком.

Сдвиги в `poses.txt` считаются от положения головы в нулевом кадре
ходьбы — именно туда посажена нарисованная голова, а у каждого клипа
своя нулевая точка.

## Палитра

По умолчанию — палитра женских паков, она в `tools/dir8/internal/grid`.
Пак может её переопределить файлом `dir8/palette.txt`: строки вида
`<символ> #RRGGBB` или `#RRGGBBAA`. Так сделаны мужские паки (своя
растяжка кожи, синие глаза, своя тень) и паки с палкой (своё древко).
Силуэты у мужских и женских голов совпадают клетка в клетку, поэтому
одна и та же сетка годится обоим — расходятся только цвета.

Новый цвет вне палитры трассировщик не пропускает молча: он берёт
ближайший и печатает предупреждение. Это не украшение — на этом
ловились уехавшая в цвет тени вспышка попадания и древко палки,
покрашенное в цвета меча.

## Сборка

```
go run ./tools/dir8/build assets/character/female/sword
```

Собирает все клипы, для которых есть каталог сеток, и кладёт рядом
`<клип>8.png` — восемь рядов. Первые четыре скопированы из исходного
листа как есть, поэтому старые индексы направлений остаются
валидными; дальше идут down_right, down_left, up_right, up_left.

Когда собраны все клипы пака, сборка заодно переводит на них
`manifest.json`: дописывает четыре направления, переставляет анимации
на восьмирядные листы и пересчитывает рамку непрозрачных пикселей
(диагонали могут её расширить, а `spriteanchor` до паков персонажа не
доходит — он обходит только мобов). Пока собраны не все клипы,
манифест не трогается: `directions` в нём один на весь пак, и
четырёхрядный лист рядом с восемью объявленными направлениями просто
не загрузится. Поэтому же правку манифеста делает сборка, а не рука:
после следующего прогона `assetnorm` достаточно собрать заново.

Снять слои нового направления:

```
go run ./tools/dir8/trace assets/character/<пак> <клип> <right|up> <каталог>
```

Уже существующие файлы трассировщик не перезаписывает — ручные правки
переживают повторный прогон.

Проверка: `go run ./tools/dir8/islands <лист>` печатает число связных
кусков в каждом кадре. У диагоналей оно обязано совпадать с эталонными
рядами: лишний кусок — это оторвавшийся меч или искра росчерка не на
месте. Остальные инструменты — `paint` (собрать один кадр), `topaint`
(перевести PNG в сетку), `zoom` (увеличить с линейкой), `mirror`.

## Что нашлось в самих паках

В верхнем ряду `idle` художник нарисовал 4 кадра, а манифест обещает
12: кадры 4-11 пустые, и во всех шести паках. Персонаж, стоящий
спиной, из-за этого пропадает на две трети цикла. В диагоналях
трассировщик повторяет нарисованную четвёрку по кругу, но сам ряд
`up` в исходных листах так и остался дырявым — это чинить отдельно.
