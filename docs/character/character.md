# Персонаж — данные и автомат (`character.json`, `internal/character`)

Каноничное описание [assets/character/character.json](../../assets/character/character.json)
и правил, по которым работает [internal/character](../../internal/character):
кто такой герой, чем вооружён, как быстро ходит и как бьёт.

Устройство повторяет животных ([species.md](../mobs/species.md)): смысл — в
рукописной таблице, графика — в сгенерированных манифестах, а расхождение между
ними закрывает деградация клипов. Разница одна: намерения приходят не от ИИ, а
от ввода игрока.

---

## 1. Разделение с `manifest.json`

| файл | что описывает | кто пишет |
|---|---|---|
| `<тело>/<лоадаут>/manifest.json` | кадры, размеры, анимации, `bbox`, `anchor` | генераторы (`assetnorm`, `spriteanchor`) |
| `character/character.json` | тела, оружие, баланс, удар | человек |

Любые ручные правки в `manifest.json` затрутся при перегенерации:

```bash
go run ./tools/assetnorm && go run ./tools/spriteanchor -root assets/character
```

`assetnorm` режет сырые паки CraftPix в наш вид и пишет манифест, `spriteanchor`
дописывает в него `bbox` и `anchor` по непрозрачным пикселям. Без второго шага
персонаж будет стоять «в воздухе»: кадр 64×64, а ноги в нём на 47-м пикселе.

---

## 2. Вариант персонажа: тело × лоадаут

Вариантов не один список, а два измерения:

- **тело** (`bodies`) — внешность: `male`, `female`. Каталог в `assets/character/`.
- **лоадаут** (`loadouts`) — чем вооружён: `unarmed`, `sword`. Подкаталог тела.

Пак пары лежит в `assets/character/<body>/<loadout>`, ключ записи == имя папки
== `art`. Наборы анимаций у тел одинаковые, у лоадаутов — нет: это и есть
причина, по которой лоадаут отдельная сущность, а не поле тела.

| пара | клипы |
|---|---|
| `*/unarmed` | `idle`, `walk`, `run`, `hurt`, `death` |
| `*/sword` | то же + `attack`, `walk_attack`, `run_attack` |

Смена оружия на лету — `Player.Equip`: позиция, здоровье и направление
сохраняются, начатый замах прерывается. Смена тела — `Player.SetBody`: здоровье
пересчитывается в той же доле (`hp_scale` у тел разный).

## 3. Поля

### `base` — общий баланс

| поле | тип | смысл |
|---|---|---|
| `hp` | int | базовое здоровье; тело домножает своим `hp_scale` |
| `speed.walk` / `speed.run` | float | скорость, мировых пикселей в секунду |
| `body_radius` | float | радиус тела. **Не** берётся из `bbox`: у пака с мечом рамка включает вылет клинка (46 px против 30 у `unarmed`), и тело от смены оружия толстеть не должно |
| `hurt.lock_ticks` | int | сколько тиков персонаж не слушается ввода после удара |
| `hurt.invuln_ticks` | int | кадры неуязвимости; следующий урон в это окно не проходит |
| `hurt.knockback` | float | отброс от источника урона, px/с |
| `death.fade_ticks` | int | сколько тает труп после доигранного `death` |
| `attack_move_scale` | 0..1 | во сколько раз медленнее движение во время удара на ходу |

### `bodies` — тела

| поле | тип | смысл |
|---|---|---|
| `art` | string | папка в `assets/character/` (== ключ) |
| `title.ru` / `title.en` | string | отображаемое имя |
| `default_loadout` | id | с чем тело выходит по умолчанию |
| `hp_scale`, `speed_scale` | float | поправки к `base` |

### `loadouts` — оружие

| поле | тип | смысл |
|---|---|---|
| `art` | string | подкаталог тела (== ключ) |
| `speed_scale` | float | поправка к скорости (без оружия бегается легче) |
| `attack` | объект | см. ниже |

### `loadouts.*.attack` — удар

| поле | тип | смысл |
|---|---|---|
| `damage` | int | урон |
| `reach` | float | радиус сектора поражения, px (к нему прибавляется `body_radius`) |
| `arc` | float | раствор сектора, градусов |
| `swing_ticks` | int | длительность замаха, тиков (60 = 1 с) |
| `cooldown_ticks` | int | перезарядка, тиков от начала замаха |
| `knockback` | float | отброс цели |
| `on_move` | bool | умеет ли лоадаут бить, не останавливаясь |
| `hit_at` | map клип→кадр | на каком кадре клипа наносится урон |

**`swing_ticks` важнее, чем кажется.** `fps` в манифесте один на весь пак — его
ставит `assetnorm` (7), и по нему взмах мечом из 8 кадров тянулся бы 1.14 с.
Длительность боевого действия — это баланс, а не свойство листа, поэтому клип
замаха растягивается под `swing_ticks`. Округление идёт вниз до целого числа
тиков на кадр: 32 тика на 6 кадров — это 5×6 = 30.

Реальный темп ударов — `max(swing_ticks, cooldown_ticks)`: новый замах не
начнётся ни посреди предыдущего, ни раньше перезарядки.

`hit_at` задаёт кадр попадания для каждого ударного клипа отдельно: у `attack`
(8 кадров) клинок опускается позже, чем у `walk_attack` (6 кадров). Клип, не
названный в `hit_at`, бьёт серединой — это и путь для `unarmed`, у которого
ударных клипов нет вовсе.

Удержание удара не буферизуется: нажатие, пришедшее в замахе, в оцепенении или
на перезарядке, просто теряется. Кто хочет автоатаку — жмёт каждый тик.

## 4. Автомат состояний

Ввод приходит структурой `character.Input` — персонаж ничего не знает про
клавиши и мышь, раскладку держит вызывающий (сцена, просмотрщик, тест):

| поле | смысл |
|---|---|
| `Move` | направление движения, длина сверх 1 обрезается (диагональ не быстрее прямой) |
| `Run` | просьба бежать |
| `Attack` | удар нажат **в этом тике** |
| `Aim` / `HasAim` | мировая точка под курсором; без прицела персонаж смотрит туда, куда идёт |

Состояния и переходы:

| состояние | когда | что может прервать |
|---|---|---|
| `Idle` | нет `Move` | всё |
| `Walk` | есть `Move` | всё |
| `Run` | есть `Move` и `Run` | всё |
| `Attacking` | `Attack` при готовой перезарядке | урон (замах сбивается, попадание не выдаётся), смерть |
| `Hurt` | получен урон | смерть |
| `Dead` | hp ≤ 0 | ничто; после `death` труп тает `fade_ticks` и `Gone()` == true |

В `Hurt` ввод не слушается, но отброс доезжает и гаснет — удар видно, а не
только слышно. В `Attacking` движение продолжается, если у лоадаута
`on_move: true` (со скидкой `attack_move_scale`), иначе персонаж встаёт.

Плавать персонаж не умеет (клипа `swim` в паках нет), поэтому вода непроходима
наравне с непроходимой сушей. Упираясь в препятствие, персонаж скользит вдоль
него: оси пробуются по отдельности, иначе он залипал бы в углах.

## 5. Деградация клипов

Набор анимаций у паков рваный, но состояние выбирается по вводу и **никогда** не
зависит от того, есть ли под него анимация. Чего нет в паке, тем и не бьём — но
ударить можно всегда:

| состояние | клип | если клипа нет |
|---|---|---|
| `Idle` | `idle` | `walk` |
| `Walk` | `walk` | замедленный вдвое `run` |
| `Run` | `run` | ускоренный вдвое `walk` |
| `Attacking` стоя | `attack` | `walk_attack` → рывок походкой (`attack*`) |
| `Attacking` шагом | `walk_attack` | `attack` → рывок |
| `Attacking` бегом | `run_attack` | `walk_attack` → `attack` → рывок |
| `Hurt` | `hurt` | `idle` → `walk` |
| `Dead` | `death` | `hurt` → `idle` → `walk` (плюс растворение) |

Имя подменыша отличается от исходного намеренно (`walk*`, `run*`, `attack*`):
проигрыватель сравнивает имена, и без «звёздочки» переход «иду» → «бью» на том
же `walk` не перезапустил бы клип.

Это ровно та же схема, что у животных, и проверяется она так же: тест гоняет
каждую пару через все состояния и падает, если хоть на одном тике рисовать
нечего.

## 6. Удар глазами игрового слоя

Персонаж не знает про своих целей — он отдаёт **область**:

```go
if h, ok := p.Strike(); ok {          // непусто ровно один раз за замах
    for _, a := range spawner.Animals() {
        if h.Covers(a.Pos, a.Radius()) {
            a.Hit(h.Damage)
        }
    }
}
```

`Strike()` возвращает `Hit` на кадре попадания (`hit_at`): центр, направление,
`Reach` (уже с прибавленным `body_radius`), `Arc`, урон и отброс. `Covers`
проверяет и расстояние, и угол; цель вплотную считается задетой всегда —
направление на неё вырождается, и угол проверять не по чему.

Обратная сторона — `p.Damage(dmg, from)`: возвращает `true`, если добил, и сам
разбирается с неуязвимостью и отбросом.

## 7. Где что лежит

| | |
|---|---|
| данные | [assets/character/character.json](../../assets/character/character.json) |
| спрайты | `assets/character/<тело>/<лоадаут>/` |
| таблица и загрузка | [internal/character/character.go](../../internal/character/character.go) |
| автомат и анимация | [internal/character/player.go](../../internal/character/player.go) |
| просмотрщик | [tools/charview](../../tools/charview) |
| нарезка паков | [tools/assetnorm](../../tools/assetnorm), [tools/spriteanchor](../../tools/spriteanchor) |

### Просмотрщик

```bash
go run ./tools/charview          # сетка: все пары, одна анимация
go run ./tools/charview -live    # живой режим: управляемый персонаж
```

**Сетка** показывает, что на самом деле лежит в паках: какие клипы есть у каждой
пары (у кого нет — клетка красная), сколько в них кадров, где точка опоры.
`[` `]` — анимация, `TAB` — направление, `F` — рамка и точка опоры, `ПРОБЕЛ` —
пауза.

**Живой режим** показывает сам автомат: `WASD` — ход, `SHIFT` — бег, `ЛКМ`/`J` —
удар, `E` — сменить оружие, `G` — тело, `H` — получить урон, `K` — смерть, `R` —
подъём. На экране состояние, имя клипа, hp и параметры удара; сектор попадания
подсвечивается на кадре, которым он наносится. Площадка с прудом — чтобы было
видно, что в воду персонаж не заходит.

Просмотрщик заодно прогоняет `Validate()` и печатает расхождения таблицы в
консоль при старте.
