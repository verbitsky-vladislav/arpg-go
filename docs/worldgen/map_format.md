# `map_format v1` — выходной формат карты

`worldgen.spec.md §3, §9.1` ссылается на `map-spec.md`, которого в репозитории
нет. Поэтому формат зафиксирован здесь и реализован в `internal/worldgen/mapformat.go`.
Файл пишется генератором как `map.json` рядом с рендерами.

## Верхний уровень

```json
{
  "format": "map_format v1",
  "biome": "forest",
  "seed": 1,
  "width": 128, "height": 128, "tile_size": 16,
  "sheets": [ { "name": "...", "file": "...", "columns": 21, "tilecount": 651, "firstgid": 7243 } ],
  "water_colors": [ [63,115,158], [58,101,139], [53,87,120] ],
  "layers": { ... },
  "props": [ ... ],
  "markers": [ { "kind": "spawn", "x": 64, "y": 61 } ],
  "nav": { "w": 256, "h": 256, "scale": 2, "cells": "<base64>" }
}
```

`sheets` упорядочены и несут `firstgid` (нумерация как в Tiled): глобальный id
тайла = `firstgid листа + локальный id`. Разрежённые слои ссылаются на лист по
индексу в этом массиве (`s`).

## Слои (`layers`) — 14 канонических, снизу вверх по стопке

| Слой | Хранение | Содержит |
|---|---|---|
| `liquid` | плотный `[]uint16` | вода/пустота; **в forest не используется** — сплошного водного тайла в наборах нет, воду красит цвет `water_colors`. Слой ждёт биомы с `edge_mode: "wall"`, где ту же роль играет сплошная порода |
| `liquid_shade` | плотный `[]uint8` | полоса глубины воды: индекс цвета в `water_colors` + 1 |
| `liquid_detail` | разрежённый | анимированная детализация воды (рябь) |
| `mud` | плотный `[]uint16` | грунт: сплошная подложка под травой, видна на тропах |
| `ground` | плотный `[]uint16` | нижний уровень |
| `ground_spots` | разрежённый | пятна покрытия на грунте троп |
| `ground_decor` | разрежённый | кустики травы по всей травяной поверхности |
| `coast` | разрежённый | переходы вода↔земля (аним) |
| `surface_liquid` | разрежённый | кувшинки |
| `plateau_shadow` | разрежённый | тень обрыва на нижнюю землю |
| `plateau` | плотный `[]uint16` | верхний уровень |
| `cliff` | разрежённый | грани обрыва |
| `stairs` | разрежённый | лестницы |
| `hangers` | разрежённый | лианы со свеса |

Порядок в таблице — порядок хранения, а не в точности порядок отрисовки:
`ground_decor` рисуется ПОСЛЕ `plateau`, иначе кустики на макушке закрывались бы
самим плато. На нижнюю землю это не влияет — там слой плато пуст.

`props` вынесены на верхний уровень как список сущностей (не тайлов).

### Плотные слои

`[]uint16` длиной `width*height`, row-major. **Кодирование: `0` = пусто,
значение `v>0` = локальный id тайла `v-1`.** Смещение на 1 нужно, чтобы отличать
пустую клетку от тайла с id 0. Каждый плотный слой рисует из одного листа
(`liquid` — из роли `liquid`, `ground` — `ground_a`, `plateau` — `plateau`).
Ограничение v1: многолистовые плотные слои не поддерживаются.

Байтовые плотные слои (`liquid_shade`, `nav.cells`) — `[]uint8`, и в JSON они
уезжают строкой base64: так их пишет `encoding/json` для любого `[]byte`. После
декодирования это row-major массив: у `liquid_shade` — `width*height` элементов
(по тайлу), у `nav.cells` — `nav.w*nav.h` (сетка мельче, см. ниже).

### `water_colors` и `liquid_shade` — цвет воды

Сплошного водного тайла в наборах нет, воду красит движок (`autotiling.md §5`).
`water_colors` — палитра от мели к глубине; `liquid_shade[i]` даёт индекс цвета
для тайла `i` (`1` = первый цвет палитры, самая светлая вода у берега; `0` — нет
данных, берётся последний цвет). Полосу считает `stageWaterShade`: расстояние до
суши, размытое шумом, плюс правило «вся внутренняя вода (пруды, реки) —
светлая». Карта без этого слоя красится одним последним цветом, как раньше.

### Разрежённые слои

Список клеток `{ "x", "y", "s", "t", "anim?" }`:
- `s` — индекс листа в `sheets`;
- `t` — локальный id тайла (без смещения);
- `anim` — `{ "frames", "stride", "ms" }`, если тайл анимирован.

## `props` — сущности

```json
{ "id": "Tree1", "file": "PNG/Objects_separated/Tree1.png",
  "x": 30, "y": 12, "w": 8, "h": 8, "anchor": [4,8], "sort_y": 19, "collides": true }
```

`x,y` — тайл верхнего-левого угла футпринта; `anchor` — низ-центр (точка на полу);
`sort_y` — ключ сортировки по глубине (рисуются вместе с игроком). Пропсы —
отдельные PNG, не часть атласа.

## `nav` — сетка физики

```json
"nav": { "w": 256, "h": 256, "scale": 2, "cells": "<base64 uint8>" }
```

Плотная сетка `cells` длиной `w*h`, row-major, по байту на **под-клетку**.
Значение — `physics.Cell`, то есть не «проходимо/нет», а ЧТО в этом месте:

| Код | Клетка | Кто проходит |
|---|---|---|
| 0 | `Deep` — глубокая вода | только пловцы (вид с `locomotion.water` и клипом `swim`) |
| 1 | `Shallow` — мелководье | вброд, скорость ×0.6 |
| 2 | `Ground` — нижняя земля | все |
| 3 | `Plateau` — макушка возвышенности | все, но это **верхний этаж** |
| 4 | `Ramp` — лестница | все; единственная связка этажей |
| 5 | `Solid` — тело обрыва, пропс | никто |

Проходимость выводит движок из клетки и возможностей тела (`internal/physics`),
поэтому она разная у героя, утки и кабана. Шаг между клетками **разных этажей**
запрещён, если ни одна из них не `Ramp`, — на возвышенность нельзя зайти сбоку,
хотя обрыв нарисован только с юга. Спрыгивать вниз тоже нельзя.

Пропс с `collides` закрывает одну клетку под своим якорем (ствол), а не весь
футпринт (крона дерева — 8 тайлов). Лестницы и воду пропсы не перекрывают.

### `scale` и сдвиг на полтайла

`scale` — под-клеток на тайл (сейчас 2, то есть под-клетка = полтайла). Мельче
смысла нет: тайл dual-grid собран из четырёх четвертей, и каждая показывает свою
клетку уровней (`autotiling.md §2`), — половина тайла это предел, ниже которого
данных всё равно нет.

**В сетку запечён сдвиг dual-grid.** Тайл в позиции `(x,y)` описывает не клетку
`(x,y)`, а область вокруг своего верхне-левого угла, поэтому содержимое клетки
`(x,y)` НАРИСОВАНО в квадрате на полтайла правее и ниже. `buildNav` учитывает
это: под-клетка `(sx,sy)` берёт содержимое клетки `((sx-1)/2, (sy-1)/2)` — той,
которая в этом месте видна. Движок читает сетку напрямую, без поправок:
под-клетка `(sx,sy)` занимает пиксели `[sx*tile/scale, +tile/scale)`.

Всё, что приходит из карты в клеточных координатах (`markers`, `props`), при
переводе в мировые пиксели сдвигается на полтайла — иначе спавн окажется не там,
где он на картинке.

## Рендер и отладочные выходы

Генератор пишет в `out/worldgen/<id>/`:
- `seed_1.png … seed_N.png` — карты на разных сидах, композит на настоящем арте
  (главная валидация: карты структурно похожи, но визуально разные);
- `debug_height.png`, `debug_moisture.png`, `debug_levels.png` — поля генерации;
- `map.json` — эта структура (для первого сида);
- `report.txt` — проверки E1–E15 с фактическими значениями.

Запуск: `go run ./tools/worldgen <biome-dir> [-seeds N] [-size N] [-scale N] [-out dir]`.
