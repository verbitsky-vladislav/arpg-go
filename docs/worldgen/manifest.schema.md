# Схема `manifest.json` — контракт биома

Дополняет `worldgen.spec.md §2`. Здесь — точный формат файла, который каждый
биом кладёт рядом со своим артом. Генератор (`tools/worldgen`) не знает слов
«лес/пустыня» — он знает роли, а манифест сопоставляет ролям конкретные тайлы
данного тайлсета. **Новый биом = новый манифест, без изменения кода.**

Манифест лежит в корне каталога биома: `assets/biomes/<id>/manifest.json`.
Все пути к арту — относительно этого каталога.

## Как получить манифест для нового биома

Ручной подбор индексов не нужен — их даёт пример карты `.tmx` из тайлсета:

```
go run ./tools/worldgen tmxhint <biome-dir>          # разбор слоёв, fill/blob-наборы
go run ./tools/worldgen tmxhint <biome-dir> emit      # черновик manifest.json в stdout
go run ./tools/worldgen index <biome-dir> <sheet>     # атлас с номерами тайлов (доводка вручную)
```

`emit` строит черновик: плотные роли (`liquid`/`ground_a`/`plateau`) выходят с
полными blob-наборами, снятыми с авторской карты; `cliff`/`transitions`/`stairs`
и пропсы — заготовки под ручную доводку. `.tmx` используется **только как
подсказка** — результат генерации создаётся с нуля из шума.

## Верхний уровень

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | идентификатор биома (совпадает с именем каталога) |
| `tile_size` | int | размер тайла в px (16) |
| `render_scale` | int | масштаб рендера (2 → на экране 32 px) |
| `edge_mode` | string | `"water"` (рамка воды) или `"wall"` (рамка стен, пещеры) |
| `sheets` | map | таблица атласов, см. ниже |
| `terrains` | map | площадные роли |
| `transitions` | map | переходы между ролями |
| `stairs`, `hangers` | object | лестницы и свесы |
| `props` | array | объекты |
| `surface` | map | поверхностные слои (кувшинки/камыш) |

## `sheets` — атласы тайлсета

Ключ — имя листа (используется в ролях). Источник геометрии тайлов.

```json
"sheets": {
  "Ground_grass": { "file": "Tiled_files/Ground_grass.png", "columns": 21, "tilecount": 651 }
}
```

`columns` задаёт, как локальный id тайла раскладывается в атласе:
`row = id / columns`, `col = id % columns` (нумерация как в Tiled). Канонический
источник сеток — атласы из `Tiled_files/` (совпадают с `columns` из `.tsx`);
копии в `PNG/` обрезаны иначе и для сеток не годятся.

## `terrains` — площадные роли

Обязательные роли (проверяет E11): `liquid` (или `solid` при `edge_mode:"wall"`),
`ground_a`, `ground_b`, `cliff`.

```json
"ground_a": {
  "sheet": "Water_coasts",
  "fill": 181,
  "blob": { "255": 181, "31": 181, "247": 186, "112": 34, ... }
}
```

- `sheet` — из какого листа берутся тайлы роли.
- `fill` — запасной «ровный» тайл (локальный id).
- `blob` — набор автотайлинга: **ключ — нормализованная 8-соседняя маска**
  (`0..255`, реально различимых ~47 — blob-47), значение — локальный id.
  Ключ вычисляется `normalizeBlob` (см. `autotile.go`): угловой бит значим лишь
  при обоих смежных ортогональных соседях. Та же функция применяется и при
  добыче из `.tmx`, и при генерации, поэтому соответствие сходится. Промах по
  ключу → ближайший по Хеммингу → `fill`.
- `edges` (только для `cliff`) — 4-битная Wang-маска N,E,S,W (`0..15`) → id.
- `anim` — `{ "frames", "stride", "ms" }` для анимированной воды/берегов
  (кадры лежат в атласе вертикально с шагом `stride` тайлов).

Порядок бит масок (совпадает с `nb8`): `0=N 1=NE 2=E 3=SE 4=S 5=SW 6=W 7=NW`.

## `transitions` — переходы

Ключ — `"<from>-><to>"`. Обязателен минимум `liquid->ground_a`.
`set` — 4-битная Wang-маска (`0..15`) → локальный id.

```json
"transitions": { "liquid->ground_a": { "sheet": "Water_coasts", "set": { ... } } }
```

## `stairs`, `hangers`

```json
"stairs":  { "sheet": "stairs_grass", "variants": [[23]], "width": 2 },
"hangers": { "sheet": "lianas", "variants": [[113]], "on": "cliff_south" }
```

`variants` — список вариантов, каждый — список локальных id футпринта лестницы
(ширина 2). Лестницы только на южной грани (в наборе есть только этот разворот).

## `props` — объекты

Размеры и якорь **меряются из PNG** (`footprint`/`anchor` — необязательные
переопределения; спека врёт про футпринты — `Bush1` = 4×4, не 1×1).

```json
{
  "id": "Tree1", "file": "PNG/Objects_separated/Tree1.png",
  "footprint": [8,8], "anchor": [4,8], "collides": true,
  "on": ["ground_a"], "zone": ["dense","mid"], "weight": 30,
  "swap_on_ground_b": "PNG/Objects_separated/..." , "prefab": false
}
```

- `on` — на каких ролях допустим (`ground_a`, `plateau`).
- `zone` — в каких зонах плотности ставится (`dense`/`mid`/`open`/`plateau`);
  зона клетки определяется влажностью и уровнем.
- `weight` — вес во взвешенном выборе внутри зоны.
- `anchor` — низ-центр футпринта, точка на полу и ключ сортировки (`sort_y`).
- `swap_on_ground_b` — файл-замена, если под якорем покрытие `ground_b`.
- `prefab` — крупные структуры (руины): ставятся редко, с расчищенной площадкой.

Пропсы генерируются авто-сканом `PNG/Objects_separated/` (см. `props_catalog.go`):
тип и параметры выводятся из имени файла (`Tree*`, `Bush*`, `*_stone_grass*`,
`*mushroom*`, `Ruin_*`), размер — из заголовка PNG.

## `surface`

```json
"surface": { "liquid": ["water_lilis"], "shallow": ["reeds"] }
```

Поверхностные наборы: кувшинки на глубокой воде, камыш на мелководье у берега.

## Нормализация тайлсетов

Файлы биомов **не переименовываются**. Различия имён/регистра/раскладки между
биомами (`ground_grass` vs `ground_source`, лава вместо воды и т.п.) поглощает
сам манифест — он ссылается на точные имена файлов конкретного биома. Проверить
готовность всех биомов: `go run ./tools/worldgen audit`.
