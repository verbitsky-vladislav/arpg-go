# Генерация карт из купленных тайлсетов

Дополняет `map-spec.md` и `worldgen-spec.md`. Здесь — как устроен реальный
тайлсет, что из него следует для генерации, и как сделать один генератор
на все 12 биомов.

> **ВНИМАНИЕ.** Раздел про blob-47 автотайлинг (§5, «пороги/маски») УСТАРЕЛ.
> Наземные поверхности размечаются по УГЛОВОЙ dual-grid схеме — см.
> **`autotiling.md`** (актуальная спека). Разделы про форму острова, реки,
> размеры и валидацию здесь остаются в силе.

Значения в ⟨скобках⟩ — проектные параметры.

## 1. Что в тайлсете на самом деле

Замерено по `forest.zip`, не предположения.

**Тайл 16×16 px.** Не 32, как в предыдущих спеках. Решение: арт остаётся
16 px, рендер идёт с масштабом 2×, на экране тайл занимает 32 px. Данные
карты и все прежние правила работают в тайлах и не меняются.

**10 тайлсетов:**

| Набор | Размер, px | Колонок | Тайлов | Роль |
|---|---|---|---|---|
| `water_detilazation` | 592×1248 | 37 | 2886 | вода, 6 кадров анимации |
| `water_detilazation_v2` | 592×1248 | 37 | 2886 | второй вариант воды |
| `Water_coasts` | 480×784 | 30 | 1470 | берега, 6 кадров |
| `Ground_grass` | 336×496 | 21 | 651 | обрывы и края возвышенности |
| `spots` | 336×256 | 21 | 336 | пятна на полу |
| `spots_rock` | 336×368 | 21 | 483 | каменные пятна |
| `stairs_grass` | 336×272 | 21 | 357 | лестницы между уровнями |
| `lianas` | 416×160 | 26 | 260 | лианы со свеса обрыва |
| `Objects` | 512×528 | 32 | 1056 | деревья, кусты, камни |
| `water_lilis` | 112×688 | 7 | 301 | кувшинки |

**Три уровня высоты, а не два.** Слои в `Forest.tmx` называются
`water` → `main_space` → `elevated_space`, между ними `stairs`, а на
обрыве висят `lianas` и лежит отдельный слой `shadow`. То есть тайлсет
изначально спроектирован под воду, нижнюю землю и **плато с обрывом**.
Это главная структурная возможность набора, и она напрямую ложится на
карту высот из `worldgen-spec.md`.

**Вода и берега анимированы.** 6 кадров по 150 мс. Кадры лежат в атласе
стопкой по вертикали с фиксированным шагом: у воды 481 тайл (13 рядов ×
37 колонок), у берегов 240 (8 рядов × 30 колонок).

**Объекты бывают в двух версиях под покрытие.** `Beige_stone_grass1` и
`Beige_stone_ground1` — один камень для травы и для голой земли. Значит
выбор варианта зависит от того, на чём объект стоит.

**Футпринты объектов, в тайлах:**

| Категория | Штук | Размеры |
|---|---|---|
| `Tree` | 14 | 4×4, 8×8 |
| `Broken_tree` | 6 | 2×2, 4×4, 8×8 |
| `Bush` | 13 | 1×1, 2×2, 4×4 |
| `Ruin_grass` / `Ruin_orange` | 10 | 2×2, 4×4, 8×8 |
| `*_stone_*` | 27 | 1×1, 2×2, 4×4 |
| `Red_mushroom` / `Brown_mushroom` | 6 | 2×2 |
| `reeds` | 3 | 2×2 |

Дерево 8×8 тайлов — это 128×128 px арта. Радиус Пуассона должен считаться
от футпринта, иначе кроны будут наезжать друг на друга.

**Использовать `PNG/Objects_separated/`,** а не упакованный атлас: файлы
названы по смыслу, и генератор ссылается на них по имени. Атлас
`Objects.png` нужен только если вы собираете свой рантайм-атлас на сборке.

## 2. Контракт тайлсета — один генератор на 12 биомов

Генератор **не знает** слов «трава», «лес», «пустыня». Он знает роли.
Каждый биом кладёт рядом с артом `manifest.json`, который сопоставляет
роли конкретным тайлам. Новый биом = новый манифест, ни строчки кода.

```json
{
  "id": "forest",
  "tile_size": 16,
  "render_scale": 2,
  "edge_mode": "water",

  "terrains": {
    "liquid":    { "sheet": "water_detilazation", "blob": {...},
                   "anim": { "frames": 6, "stride": 481, "ms": 150 } },
    "ground_a":  { "sheet": "Ground_grass", "blob": {...} },
    "ground_b":  { "sheet": "spots",        "blob": {...} },
    "plateau":   { "sheet": "Ground_grass", "blob": {...} },
    "cliff":     { "sheet": "Ground_grass", "edges": {...} }
  },

  "transitions": {
    "liquid->ground_a": { "sheet": "Water_coasts", "set": {...},
                          "anim": { "frames": 6, "stride": 240, "ms": 150 } },
    "ground_a->ground_b": { "sheet": "spots", "set": {...} }
  },

  "stairs":  { "sheet": "stairs_grass", "variants": [...], "width": 2 },
  "hangers": { "sheet": "lianas", "variants": [...], "on": "cliff_south" },

  "props": [
    { "id": "Tree1",  "file": "Objects_separated/Tree1.png",
      "footprint": [4,4], "anchor": [2,4], "collides": true,
      "on": ["ground_a"], "zone": ["dense","mid"], "weight": 30 },
    { "id": "Beige_stone_grass1", "file": "...", "footprint": [1,1],
      "collides": false, "on": ["ground_a"], "weight": 10,
      "swap_on_ground_b": "Beige_stone_ground1" }
  ],

  "surface": { "liquid": ["water_lilis"], "shallow": ["reeds"] }
}
```

Обязательные роли, которые должен закрыть каждый из 12 манифестов:
`liquid`, `ground_a`, `ground_b`, `cliff`, `stairs`, плюс минимум один
переход `liquid->ground_a`. Если биом без воды (пещера), `liquid`
заменяется на `solid`, а `edge_mode` ставится в `wall`.

`swap_on_ground_b` решает проблему `_grass` / `_ground` вариантов: одна
запись пропса, движок подменяет файл по покрытию под якорем.

## 3. Слои

26 слоёв в `Forest.tmx` — это авторская раскладка для ручной работы в
Tiled. Для генератора они сворачиваются в 12 канонических. Порядок —
снизу вверх, он же порядок отрисовки.

| # | Слой | Хранение | Что содержит |
|---|---|---|---|
| 1 | `liquid` | плотный массив | вода или пустота |
| 2 | `liquid_detail` | плотный | детализация воды, анимированная |
| 3 | `ground` | плотный | нижний уровень, `main_space` |
| 4 | `ground_spots` | разрежённый | пятна покрытия, `spots1/2` |
| 5 | `coast` | разрежённый | переходы вода↔земля, анимированные |
| 6 | `surface_liquid` | разрежённый | кувшинки |
| 7 | `plateau_shadow` | разрежённый | тень обрыва на нижнюю землю |
| 8 | `plateau` | плотный | верхний уровень, `elevated_space` |
| 9 | `cliff` | разрежённый | вертикальные грани обрыва |
| 10 | `stairs` | разрежённый | лестницы |
| 11 | `hangers` | разрежённый | лианы со свеса |
| 12 | `props` | список сущностей | всё из `Objects_separated` |

Слои 1, 3, 8 — плотные `uint16` массивы. Остальные разрежённые: список
`{x, y, tile}`. На карте 512×512 плотный слой весит 512 КБ, три таких —
1.5 МБ, это нормально.

`props` — не массив тайлов, а список сущностей с якорем и футпринтом,
сортируется по `sort_y` вместе с игроком (см. `map-spec.md` раздел 3).

Тень плато (слой 7) рисуется ПОД плато, но НАД нижней землёй. Она даёт
ощущение высоты и идёт в комплекте с тайлсетом — не пропустить.

## 4. Размеры и закрытие краёв

```
малая карта      128×128 тайлов
обычная          256×256
большая          512×512     ← по умолчанию для открытых биомов
```

Все размеры кратны 16 (регион из `map-spec.md`). 512×512 при тайле 16 px
и масштабе 2× — это 16384 экранных пикселей в поперечнике, порядка
восьми экранов на 1920. Это «достаточно большая».

**Закрытие края — обязательное правило.** Карта конечна, игрок не должен
видеть обрыв массива.

```
edge_mode = "water"   → рамка из liquid шириной ⟨12⟩ тайлов по периметру,
                        суша не приближается к границе массива ближе
                        чем на 12 тайлов
edge_mode = "wall"    → рамка из solid шириной ⟨6⟩ тайлов,
                        внешние 3 ряда — indestructible
```

Рамка режется не прямой линией: её внутренняя граница задаётся тем же
шумом, что и весь рельеф, просто с принудительным сдвигом высоты вниз
у края:

```
edge = distance_to_border / EDGE_FALLOFF        // 0 у края, 1 внутри
h_final = h_noise - (1 - clamp(edge,0,1))^2 * 1.5
```

Так берег у края выглядит естественным, а не обрезанным по линейке.
`EDGE_FALLOFF = ⟨20⟩` тайлов.

## 5. Пайплайн

Расширяет `worldgen-spec.md` раздел 6 под три уровня высоты.

```
 1. height       fBm + domain warp (параметры из worldgen-spec §3)
 2. edge         принудительный спад высоты у границы, формула выше
 3. moisture     вторая карта шума
 4. levels       классификация по порогам, таблица ниже
 5. smooth       клеточный автомат, 3 итерации, большинство 5 из 8
 6. islands      flood fill: куски суши < ⟨80⟩ тайлов затапливаются,
                 куски плато < ⟨40⟩ тайлов срезаются до нижнего уровня
 7. plateau_fix  плато шириной меньше 4 тайлов срезается —
                 на нём не помещается лестница
 8. stairs       раздел 6, ставятся ДО растительности
 9. connectivity проверка достижимости, при провале — добавить лестницу
                 или срезать недостижимое плато
10. coast        расстановка переходных тайлов вода↔земля по битовой маске
11. cliff        грани обрыва по южной и боковым границам плато
12. shadow       тень плато на нижнюю землю, смещение ⟨2⟩ тайла вниз
13. hangers      лианы на южных гранях обрыва, ⟨25%⟩ клеток
14. terrain      ground_a / ground_b по влажности, переходные зоны 2-4 тайла
15. spots        пятна покрытия, разрежённый слой
16. props        Пуассон с переменным радиусом, раздел 7
17. surface      кувшинки на глубокой воде, камыш на мелкой у берега
18. markers      spawn, выходы, границы камеры
19. nav          пересчёт проходимости
20. validate     разделы V, W из прежних спек + T ниже
```

**Пороги уровней.** Единые для всех биомов, конкретные тайлы даёт манифест.

| h_final | Уровень | Проходимость |
|---|---|---|
| < 0.22 | `liquid_deep` | непроходимо |
| 0.22 … 0.32 | `liquid_shallow` | ×0.6, камыш растёт здесь |
| 0.32 … 0.68 | `ground` | ×1.0 |
| > 0.68 | `plateau` | ×1.0, попасть только по лестнице |

## 6. Лестницы — узкое место связности

Плато недостижимо, если к нему нет лестницы. Это самая частая ошибка
генератора такого типа, и она ломает карту целиком.

```
Для каждой связной компоненты плато:
  1. собрать все клетки южной границы (обрыв смотрит вниз-к-камере)
  2. отфильтровать те, где ниже ≥⟨3⟩ тайла свободной земли подряд
  3. если кандидатов нет — компонента срезается до уровня ground
  4. иначе поставить ⟨1 + площадь/400⟩ лестниц, но не меньше 1
  5. между лестницами одной компоненты минимум ⟨16⟩ тайлов
  6. ширина лестницы 2 тайла, по бокам не ставится ничего
```

Лестницы только на южной грани: в наборе `stairs_grass` есть только этот
разворот. Если поставить на боковую грань, спрайт не сойдётся с обрывом.

## 7. Расстановка объектов

Пуассон с переменным радиусом (`worldgen-spec.md` §7.1), но радиус
считается от футпринта, а не константой:

```
r = max(base_r(зона), (w + h) / 2 + 1)
```

Для дерева 8×8 это даёт минимум 9 тайлов между стволами — иначе кроны
128 px наезжают одна на другую.

**Якорь объекта** — нижняя середина футпринта, она же точка на полу и
ключ сортировки. У дерева 4×4 якорь `[2, 4]`.

**Маски-исключения:** вода и мелководье, лестницы плюс отступ 2 тайла,
клетки обрыва плюс отступ 1, ⟨6⟩ тайлов вокруг точки появления игрока,
футпринты структур.

**Выбор варианта по покрытию.** Если под якорем `ground_b`, а у пропса
задан `swap_on_ground_b` — подставить его. Иначе взять как есть.

**Плотность по зонам** (объектов на 100 тайлов):

| Зона | Деревья | Кусты | Камни |
|---|---|---|---|
| открытая | 1 … 3 | 4 … 8 | 2 … 4 |
| переходная | 4 … 8 | 6 … 12 | 2 … 5 |
| густая | 10 … 18 | 8 … 15 | 1 … 3 |
| плато | 2 … 5 | 3 … 7 | 6 … 12 |

Руины (`Ruin_*`, до 8×8) — не пропсы, а префабы: ставятся на шаге
структур, по одной на ⟨4096⟩ тайлов площади, с расчищенной площадкой.

## 8. Валидация — добавить к прежним

| # | Проверка | Порог |
|---|---|---|
| E1 | Рамка по краю сплошная, суша не ближе 12 тайлов к границе | обязательно |
| E2 | Внутренняя граница рамки не содержит прямых участков > 8 тайлов | 0 |
| E3 | Компонент плато без лестницы | 0 |
| E4 | Плато шириной < 4 тайлов | 0 |
| E5 | Все маркеры достижимы от точки появления | 100% |
| E6 | Доля суши от площади карты | ⟨45 … 70%⟩ |
| E7 | Доля плато от площади суши | ⟨10 … 30%⟩ |
| E8 | Пропсы пересекаются между собой или с водой | 0 |
| E9 | Пропсы в 2 тайлах от лестницы | 0 |
| E10 | Клеток `cliff` без плато сверху | 0 |
| E11 | Роли манифеста, оставшиеся незакрытыми | 0 |
| E12 | Ссылка на файл пропса, которого нет на диске | 0 |

E3 и E4 — те, ради которых стоит писать валидатор. Недостижимое плато
выглядит нормально на скриншоте и обнаруживается только в игре.

## 9. Выдача генератора

1. JSON карты в формате `map_format v1` со слоями раздела 3.
2. Отладочный экспорт в PNG: карта высот, карта влажности, карта уровней
   в оттенках серого. Без них параметры шума не подобрать.
3. ASCII-превью: `~` глубокая вода, `-` мелководье, `.` земля,
   `^` плато, `=` лестница, `T` дерево, `R` руина, `@` спавн.
4. Отчёт E1-E12 с фактическими значениями.
5. **Шесть сидов сеткой 3×2 в ASCII.** Если все шесть похожи структурно,
   но различаются в деталях — генератор верный. Если хоть один вышел
   пустым полем или лабиринтом — параметры шума не сходятся.
6. Экспорт в `.tmx`, чтобы открыть результат в Tiled и посмотреть глазами
   на настоящем арте. Это самая быстрая проверка из всех.
