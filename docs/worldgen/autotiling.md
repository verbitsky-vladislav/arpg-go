# Автотайлинг биомов — угловая dual-grid схема

Каноничное описание того, как `tools/worldgen` строит карту из размеченных
художником тайлсетов. **Это актуальная спека автотайлинга; blob-47 из
`worldgen.spec.md §5` устарел и не используется для наземных поверхностей.**

Принцип: генератор сам НИЧЕГО не рисует, кроме воды-фона. Всё остальное — это
раскладка тайлов из ручной разметки (Wang-наборов type="corner") в `.tsx`.
Художник размечает тайлы → мы описываем роли в манифесте → программа-автотайлер
выбирает нужный тайл для каждой клетки по её окружению. Проверено на `forest`.

---

## 1. Угловая (corner) схема, а не рёберная

Купленные тайлсеты построены по **угловой схеме на 16 комбинаций**, а не по
рёберной blob-47. Это была главная развилка: поиск 47 тайлов по рёбрам —
недоразумение, их там нет.

Тайл клетки задаётся четырьмя её **углами** в порядке **NW, NE, SE, SW**. Каждый
угол либо принадлежит террейну (1), либо нет (0) → 16 комбинаций (15 значимых,
16-я «все нули» = пусто). Граница террейна проходит через центры клеток, поэтому
берег/кромка выходят мягкими и органичными, без ступенек. Рёберная схема так не
умеет в принципе.

Ключ комбинации — строка `"NW,NE,SE,SW"` из 1/0, напр. `"1,1,0,1"`. Совпадает с
ключом в разметке `.tsx` и в манифесте (`grid.go: cornerKeyStr`).

---

## 2. Dual-grid: как считается ключ клетки

Ключевое решение. Террейн задан ПО КЛЕТКАМ (сетка уровней: вода/суша/тропа). Но
тайл ставится на **пересечении** клеток — по правилу dual-grid:

```
тайл в позиции (x,y) определяется четырьмя клетками, сходящимися
в его ВЕРХНЕ-ЛЕВОМ углу:
    NW = клетка (x-1, y-1)      NE = клетка (x,   y-1)
    SW = клетка (x-1, y)        SE = клетка (x,   y)
угол помечен 1, если эта клетка принадлежит террейну (present).
```

(`grid.go: cornerKey`)

**Почему именно так.** Раньше ключ считался по правилу «угол внутри, если ≥2 из 4
примыкающих клеток внутри» (заливка). Оно годится для сплошного массива, но у
границы двух террейнов (трава↔вода) даёт на ПРЯМОМ ребре комбинацию `1,1,1,1`
(все углы «внутри») → цельный тайл травы вплотную к воде, без берега. Береговой
тайл вставал только на редких выступах.

Dual-grid снимает это: на прямом вертикальном берегу (слева суша, справа вода)
клетка-тайл видит слева 2 клетки суши, справа 2 клетки воды → комбинация
`1,0,0,1` (или зеркально) → правильный переходный тайл берега. Переход
появляется на КАЖДОЙ границе, включая прямые рёбра.

Побочный эффект — сдвиг картинки на полтайла (тайл описывает область вокруг
своего верхне-левого угла). Он единообразен для всех слоёв, поэтому визуально
безвреден: вода-фон сплошная, а трава и тропы считают ключ одинаково и совпадают.

Клетки, у которых ни один угол не принадлежит террейну (`k` все нули),
пропускаются. Суша всегда ≥ `EdgeBorder` (12) клеток от края массива, поэтому
береговые тайлы не выходят за пределы плотных слоёв `W×H`.

## 3. Разрешение тайла по ключу (`resolveCorner`, варианты)

`autotile.go: resolveCorner(set, k)`:

1. Точное совпадение ключа `k` в наборе → берём его тайлы.
2. Промах → ближайший по Хеммингу ключ (число различающихся углов). Гарантирует,
   что дырки покрытия не роняют рендер.

Набор хранит **все** тайлы комбинации (`map[string][]int`), а не один — художник
рисует по 1–3 варианта на комбинацию для разнообразия. Конкретный вариант
выбирается детерминированно по позиции и сиду (`autotile.go: variantAt`):
одинаковый seed → одинаковая карта, но соседние клетки берут разные тайлы, и
поверхность не выглядит плоской штамповкой.

Таблицы углов грузятся из `.tsx` при загрузке манифеста
(`manifest.go: loadWangsets`, `parseWangCorners`): читаются все wangset'ы
`type="corner"`, `wangid` (8 значений `top,NE,right,SE,bottom,SW,left,NW`)
сводится к 4 углам `NW=idx7, NE=idx1, SE=idx3, SW=idx5`. Источник истины —
ручная разметка в Tiled, не автоизвлечение.

## 4. Двухпроходная поверхность + берег (`paintLand`)

Каждая наземная поверхность красится в ДВА прохода: **подложка** (`*_underlay`)
снизу, **поверхность** сверху. Внимание к названию: «overlay» в исходном
тайлсете вводило в заблуждение — это подложка, рисуется СНИЗУ; переименовано в
`underlay`.

Для каждой клетки (`autotile.go: paintLand`) по ключу `k`:

- **подложка** — `underRole[k]` в нижний плотный слой (всегда).
- **поверхность** — выбор по ситуации:
  - `k == 1,1,1,1` (все углы — суша) → **интерьер**, `fullRole` (напр. `grass_ground`);
  - иначе клетка граничит с водой → **берег**, `waterRole` (`grass_water`/`mud_water`);
  - иначе (граница с другой сушей/тропой) → **кромка**, `edgeRole` того же материала.

Берег лежит на ДРУГОМ листе (`Water_coasts`), поэтому пишется не в плотный слой,
а в разрежённый слой `coast` со своим листом. Интерьер/кромка/подложка (лист
`Ground_grass`) — в плотные слои. Пустые роли просто пропускаются (сквозь
прозрачные углы виден нижний слой или вода-фон).

«Граничит с водой» = среди 8 соседей клетки есть жидкая (`Level.isLiquid`).

## 5. Слои и порядок отрисовки

Снизу вверх (`render.go`):

```
0. вода            — СПЛОШНОЙ ЦВЕТ-ФОН (water_color), не тайл
1. ground_under    — grass_underlay   (подложка травы,  Ground_grass, плотный)
2. ground          — grass_ground     (интерьер травы,  Ground_grass, плотный)
3. mud_under       — mud_underlay     (подложка тропы,  Ground_grass, плотный)
4. mud             — mud              (тропа поверх травы, Ground_grass, плотный)
5. coast           — grass_water/mud_water (берега, Water_coasts, разрежённый)
```

**Вода — единственное, что генератор «рисует» сам**, потому что в `Water_coasts`
нет сплошного водного тайла (проверено: 0 непрозрачных синих тайлов; вода в
наборах — прозрачный фон, сквозь который в оригинале просвечивал
`water_detilazation`). Цвет снят усреднением синих пикселей берегов: RGB
`(53,87,120)`, задаётся в манифесте полем `water_color`.

Ничего больше (декор, пропсы, `water_detilazation`, `spots`, `Objects`) в этой
конфигурации НЕ используется — только 2 листа и ручные наборы.

## 6. Роли манифеста — единый словарь для всех биомов

`manifest.json` биома. Роль → лист + имя wangset'а (+ запасной `fill` = тайл
комбинации `1,1,1,1`). Угловая таблица подтягивается из `.tsx` листа.

| Роль | Лист | Wangset | Смысл |
|---|---|---|---|
| `ground_under` | Ground_grass | `grass_underlay` | подложка нижней земли |
| `ground` | Ground_grass | `grass_ground` | поверхность нижней земли (менее детальная) |
| `mud_under` | Ground_grass | `mud_underlay` | подложка тропы/грунта |
| `mud` | Ground_grass | `mud` | грунт/тропа |
| `grass_water` | Water_coasts | `grass_water` | берег трава↔вода |
| `mud_water` | Water_coasts | `mud_water` | берег грунт↔вода |

Плюс верхнеуровневое `"water_color": [53,87,120]`.

Обязательные роли (валидатор): `ground_under`, `ground` (`manifest.go:
requiredRoles`). Воду обеспечивает `water_color`, отдельная роль не нужна.

Заготовлено художником, но пока НЕ подключено к генерации (следующие рычаги):
`grass_cliff` (верх плато), `*_start_bridge` (мосты через воду).

Пример:

```json
{
  "id": "forest",
  "tile_size": 16,
  "render_scale": 2,
  "edge_mode": "water",
  "water_color": [53, 87, 120],
  "sheets": {
    "Ground_grass": { "file": "tiles/Ground_grass.png", "columns": 21, "tilecount": 651 },
    "Water_coasts": { "file": "tiles/Water_coasts.png", "columns": 30, "tilecount": 1470 }
  },
  "terrains": {
    "ground_under": { "sheet": "Ground_grass", "wangset": "grass_underlay", "fill": 476 },
    "ground":       { "sheet": "Ground_grass", "wangset": "grass_ground",   "fill": 590 },
    "mud_under":    { "sheet": "Ground_grass", "wangset": "mud_underlay",    "fill": 371 },
    "mud":          { "sheet": "Ground_grass", "wangset": "mud",             "fill": 422 },
    "grass_water":  { "sheet": "Water_coasts", "wangset": "grass_water",     "fill": 181 },
    "mud_water":    { "sheet": "Water_coasts", "wangset": "mud_water",       "fill": 61  }
  }
}
```

## 7. Структура каталога биома

```
assets/biomes/<id>/
  manifest.json          # контракт роли→наборы + water_color
  tiles/                 # листы-атласы .png + их разметка .tsx (вместе; source= = имя файла)
    Ground_grass.png  Ground_grass.tsx
    Water_coasts.png  Water_coasts.tsx
  props/                 # (опц.) отдельные спрайты объектов — в этой конфигурации не используются
  authoring/             # НЕ идёт в движок: forest.tmx (карта художника) + .tiled-project
```

`.tsx` лежат РЯДОМ с их `.png`, поэтому `source="Ground_grass.png"` (голое имя).
Движку в рантайме нужны только `*.png` + `manifest.json` + карта; `.tsx/.tmx/
.tiled-project` — авторинг, в билд не идут.

## 8. Пайплайн генерации формы

Тайлы — из разметки, но ФОРМА карты (где вода/суша/тропа) генерится с нуля из
шума (`pipeline_run.go: Run`):

1. `stageHeight` — fBm + domain warp, спад высоты у края (рамка воды).
2. `stageMoisture`, `stageLevels` — классификация клеток по порогам.
3. `stageSmooth`, `stageIslands`, `stagePlateauFix` — сглаживание, заливка мелких
   кусков, срез узких плато.
4. `forceEdgeRing` — гарантированная водяная рамка ≥12 клеток по периметру.
5. `dropPlateau` — плато пока срезается до нижней земли (обрыв не собран).
6. `stageWater` — пруды (круги с шумовой каймой) + извилистые реки
   (`curves.go`: A* → меандр → сглаживание Чайкина → круглая кисть).
7. `stageTrails` — сеть грунтовых троп тем же конвейером, ширина кисти ~3 клетки
   (у́же — у углового автотайла нет клетки заливки, тропа рассыпается).
8. `paintLand` для травы и для троп (§4).
9. `stageMarkers` — точка спавна.

## 9. Что нужно сделать художнику для нового биома (Tiled)

Чтобы биом заработал БЕЗ единой строчки кода:

1. **Разложить арт** в `assets/biomes/<id>/tiles/` (листы `.png`). Сгенерировать
   болванки `.tsx`: `python3 tools/pngtotsx.py <id>/tiles --batch`.
2. **Разметить угловые наборы** в Tiled (Terrain/Wang, обязательно `type="corner"`),
   именами из словаря §6:
   - на листе земли: `grass_underlay`, `grass_ground`, `mud_underlay`, `mud`
     (позже `grass_cliff` для плато);
   - на листе берегов: `grass_water`, `mud_water` (позже `*_start_bridge`).
   Каждый набор — все 15 значимых комбинаций; можно по 1–3 варианта тайла на
   комбинацию (для разнообразия). Углы ставить ПРАВИЛЬНО: угол = 1 там, где тайл
   показывает материал, 0 — где переход/другой материал.
3. **Собрать манифест**: `go run ./tools/worldgen tmxhint <id> emit` даёт черновик
   (снимает геометрию листов, воду, пропсы с карты-примера), затем дописать
   угловые роли §6 и `water_color`. Или скопировать forest и заменить листы.
4. **Проверить**: `go run ./tools/worldgen assets/biomes/<id>` — 6 карт на разных
   сидах в `out/worldgen/<id>/`. Структурно похожи, но разные в деталях = набор
   верный. Валидатор E1–E12 в `report.txt`.

Ключевое правило разметки: **набор — угловой (`type="corner"`)**. Рёберный/mixed
не подойдёт — программа считает ключ по 4 углам dual-grid (§2).
