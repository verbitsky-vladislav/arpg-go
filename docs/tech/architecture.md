# Архитектура проекта

Пиксельная ARPG (в духе Path of Exile: hack&slash + гринд), но **мобы атакуют**.
Графика — двумя способами: игрок/мобы/снаряды рисуются **процедурно в коде**
из пиксельных карт (`gfx`/`art`); **герои** — это PNG-кадры (тоже сгенерированы
кодом), вшитые через `//go:embed` и проигрываемые покадрово (`assets`/`anim`/`hero`).

## Дерево

```
game/
├── main.go                  точка входа: окно + запуск core
├── go.mod / go.sum
├── docs/                    документация
│   ├── ROADMAP.md           план развития
│   ├── mechanics/           game design: описания игровых механик
│   └── tech/                техническое (этот файл — tech/architecture.md)
├── assets/                  ресурсы, вшиваются в бинарник через //go:embed
│   └── sprites/heroes/<id>/  base.png + idle|walk|attack|punch|take_damage|loot (16 кадров)
├── tools/spritegen/         CLI-генератор кадров героев из base.png (не в игре)
└── internal/                весь код игры (не импортируется извне)
    ├── config/    константы: размеры экрана/мира, TPS, баланс
    ├── engine/    вектор Vec2, математика, камера
    ├── gfx/       генератор спрайтов из пиксельных карт (ядро «рисуем кодом»)
    ├── anim/      покадровая анимация: Clip (кадры+тайминг) + Player (проигрыватель)
    ├── assets/    загрузка PNG из fs.FS (embed) в *ebiten.Image, с кэшем
    ├── combat/    типы урона, характеристики Stats, снижение урона
    ├── item/      предметы, оружие, редкость (задел под лут/аффиксы)
    ├── skill/     описания умений (данные: мана, кулдаун, урон снаряда)
    ├── art/       конкретные спрайты игры (игрок, мобы, снаряды)
    ├── hero/      реестр героев: ID, действия, ленивая загрузка клипов анимаций
    ├── entity/    сущности: player, mob, projectile + интерфейс World
    ├── world/     мир: спавн, столкновения, камера, отрисовка сцены
    ├── ui/        HUD + виджеты (Button, TextCentered, DrawSpriteFit)
    ├── scene/     экраны: menu, play, heroselect (+ showcase) + машина переходов
    └── core/      тип Game (реализует ebiten.Game), делегирует активной сцене
```

## Слои зависимостей (стрелка = «импортирует»)

```
main → core → scene → world → entity → art  → gfx
  │      │      │        │        │       └───→ combat
  │      │      │        │        ├─────→ item → combat
  │      │      │        │        ├─────→ skill → combat
  │      │      │        │        └─────→ engine
  │      │      │        ├─────→ ui → combat, config
  │      │      │        └─────→ config, engine
  │      │      └─────→ hero → anim, assets   (экран heroselect)
  │      └────────────→ hero, assets, config
  └───────────────────→ assets (//go:embed), config
```

`assets` и `anim` — нижние слои: знают только про `ebiten`, ничего игрового.
`hero` связывает их с предметной моделью (какие герои, какие действия, тайминги).
Загрузчик ассетов создаётся в `main` из вшитой `embed.FS` и **инъектируется**
в `core.New(*assets.Loader)` → далее в `scene.NewMenu` → `heroselect`.

**Правило:** зависимости идут только вниз. Нижние слои (`config`, `engine`,
`gfx`, `combat`, `anim`, `assets`) ничего игрового не знают. Это исключает
**циклы импортов** (в Go они запрещены на уровне компилятора).

## Ключевой приём против цикла: узкий интерфейс `World`

`entity` не импортирует `world`. Вместо этого в `entity` объявлен интерфейс
`World` (что сущность умеет делать с миром: `AddProjectile`, `Player`, `Mobs`,
`CursorWorld`). Реализует его `world.World`. Так `world` знает про `entity`,
а `entity` про `world` — нет. Тот же приём применяем для любых будущих
взаимодействий «сущность ↔ мир».

## Как рисуется графика — два пути

### A. Процедурно из пиксельных карт (игрок, мобы, снаряды)

1. Спрайт — это `[]string` (пиксельная карта) + палитра `map[rune]color`.
2. `gfx.NewSprite(rows, palette, scale)` строит `*ebiten.Image` один раз.
3. Пакет `art` хранит все карты и кэширует готовые изображения.
4. Логическое разрешение маленькое (640×360), окно 1280×720 → чёткие «жирные»
   пиксели за счёт масштабирования окном.

Хочешь нового моба/оружие/эффект — добавляешь пиксельную карту в `art`.

### B. PNG-кадры героев (embed → загрузка → покадровое проигрывание)

1. Кадры лежат в `assets/sprites/heroes/<id>/<action>/frame_NN.png` (16 шт.),
   сгенерированы инструментом `tools/spritegen` из `base.png` (отдельный
   `package main`, в игровой бинарник не входит; перегон:
   `go run ./tools/spritegen assets/sprites/heroes`).
2. `main.go` вшивает каталог: `//go:embed all:assets`, затем `fs.Sub` срезает
   префикс `assets/` и оборачивает во `assets.NewLoader(fsys)`.
3. `assets.Loader.Frames(dir)` читает отсортированные `frame_*.png`, декодирует
   в `*ebiten.Image` и кэширует.
4. `hero.Registry`/`hero.Hero` **лениво** собирают из кадров `anim.Clip`
   (кадры + `FrameTicks` + `Loop`) по таблице `hero.actionDefs`.
5. `anim.Player` проигрывает клип во времени (`Update`/`Frame`) — по одному
   независимому проигрывателю на сущность/карточку. Механизм общий: годится для
   мобов, эффектов, UI — не только героев.

Хочешь нового героя — кладёшь спрайты в `assets/...`, добавляешь `hero.ID`
в реестр. Хочешь новую анимацию действия — добавляешь запись в `hero.actionDefs`
и каталог с кадрами.

## Игровой цикл

- `core.Game.Update()` → `scene.Update()` → `world.Update()`:
  игрок/мобы/снаряды двигаются, затем `collisions()` наносит урон, `cleanup()`
  убирает мёртвых, `spawn()` подкидывает мобов.
- `core.Game.Draw()` → `scene.Draw()` → `world.Draw()` (фон, сетка, сущности) +
  `ui.DrawHUD()`. Послойная модель отрисовки пространств (пол/декали/сущности/стены/
  надземное, Y-sort) — `rendering.md` (спроектировано; сейчас код рисует плоско).
- 60 TPS (логика), FPS = частота монитора.

## Куда что добавлять (шпаргалка)

| Хочу…                        | Иду в пакет           |
|------------------------------|-----------------------|
| новый тип урона/резист       | `combat`              |
| новое умение                 | `skill` (+ `entity` если новая механика снаряда) |
| новое оружие/предмет/аффикс  | `item`                |
| нового моба                  | `entity` (статы) + `art` (спрайт) |
| новый спрайт/эффект           | `art` (+ `gfx` если новый примитив) |
| нового героя / его спрайты    | `assets/sprites/heroes/<id>/` (+ `tools/spritegen`) + `hero` (реестр) |
| новое действие-анимацию       | `hero.actionDefs` + каталог кадров (+ `tools/spritegen`) |
| перегенерировать кадры героев  | `tools/spritegen` (правишь `base.png` → перегон) |
| покадровую анимацию чему-либо | `anim` (Clip + Player) |
| элемент интерфейса / виджет   | `ui`                  |
| новый экран (инвентарь, дерево умений) | `scene`     |
| настройку баланса/размеров    | `config`              |
```
