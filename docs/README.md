# Документация игры

Документы разделены, чтобы **не мешать game design и технику**:

- **`vision.md`** — полярная звезда: что это за игра, ради чего. С неё начинается всё.
- **`design/`** — *визуал и подача*: лор, арт, атмосфера, звук, интерфейс.
- **`mechanics/`** — *системы и правила*: бой, персонажи, умения, мобы, лут.
- **`progression/`** — *развитие*: дерево прокачки, рост персонажа, эндгейм.
- **`tech/`** — *как устроено технически*: архитектура, пакеты, снимок реализации.
- **`mvp.md`** — scope MVP и трекер «что осталось» (дизайн ↔ код).
- **`ROADMAP.md`** — этапы разработки.

## Порядок работы (спина → ветки)

Заполняем не всё сразу, а по важности:

1. `vision.md` — концепт, пиллары, фантазия игрока.
2. `mechanics/core-loop.md` — ядро геймплея (петля).
3. Дальше — ветки (combat, characters, art, skill-tree...), **каждую создаём,
   когда дошли до неё в обсуждении**. Пустые заготовки не плодим.

Каждый раздел (`design/`, `mechanics/`, `progression/`) имеет свой `README.md`
с картой файлов и статусами.

## Как писать доки

Единый шаблон для файла механики/дизайна:

```markdown
# Название

Статус: ⚪ задумано · 🟡 частично · 🟢 в игре
Связь с кодом: internal/... (или «—», если ещё нет)

## Идея        — 1–2 предложения, суть
## Как работает — правила
## Числа        — формулы, значения (если есть)
## Ощущение     — что должен чувствовать игрок (feel)
## Открытые вопросы
## Связь с пилларами — какие пиллары из vision.md обслуживает
```

Правило: в `mechanics/` и `progression/` — **дизайн** (правила, числа, ощущения),
а не код. Технические детали (имена типов, пакеты) — в `tech/`.
```
