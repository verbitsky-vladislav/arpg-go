# Враги и боссы — описательные данные (`enemies.json`, `bosses.json`)

Каноничное описание [assets/mobs/enemies/enemies.json](../../assets/mobs/enemies/enemies.json)
и [assets/mobs/bosses/bosses.json](../../assets/mobs/bosses/bosses.json):
кто это, где водится, как дерётся и что достаётся игроку при убийстве.

Устройство то же, что у животных ([species.md](species.md)): смысл — в рукописной
таблице, графика — в сгенерированных манифестах. Читает обе таблицы один
загрузчик [internal/mob/enemies.go](../../internal/mob/enemies.go): формат у них
общий, боссовые поля просто не заполнены у врагов.

---

## 1. Два уровня: тип и тир

У животных запись плоская — один вид, один набор чисел. У врагов так не выходит:
каждый тип нарисован **в трёх силах подряд** (`t1`, `t2`, `t3`), а у слизней
вместо тиров девять цветов. Плоско это дало бы 60 записей с трёхкратным повтором
смысловых полей.

Поэтому запись двухуровневая:

| уровень | что в нём | пример |
|---|---|---|
| **тип** | смысл: семья, характер, биомы, дроп, сила | `demon` |
| **тир** | числа особи: hp, урон, скорость, опыт | `demon.tiers.t3` |

Сквозной идентификатор варианта — `<тип>_<тир>` (`demon_t1`, `slime_lava`). Он
совпадает с полем `id` в манифесте пака, и тест это проверяет: по нему
связываются данные и графика, а разойтись они могут молча.

Путь к спрайтам собирается из тех же двух ключей:
`assets/mobs/enemies/<art>/<тир>` — то есть `art` == ключ типа, ключ тира == имя
папки.

---

## 2. Поля типа

### Кто это

| поле | тип | смысл |
|---|---|---|
| `art` | string | папка со спрайтами (== ключ записи) |
| `title.ru` / `title.en` | string | имя типа; у тиров свои имена |
| `family` | enum | `undead`, `demon`, `spirit`, `beast`, `humanoid`, `plant`, `fungus`, `construct`, `ooze`, `aberration` |
| `size_class` | enum | `small` / `medium` / `large` — смысловой размер, не пиксельный |

### Как дерётся

| поле | тип | смысл |
|---|---|---|
| `temper` | enum | `aggressive` — идёт на игрока; `territorial` — только при вторжении; `ambusher` — замечает поздно, но не отпускает; `ranged` — держит дистанцию |
| `activity` | enum | `day` / `night` / `any` |
| `locomotion.ground` / `.air` | bool | летающих (призрак, бехолдер) не держат вода и обрывы |
| `threat.attacks` / `.unprovoked` | bool | может напасть / нападает первым |
| `threat.sight` | float | радиус обнаружения, px мира |
| `threat.reach` | float | с какой дистанции достаёт игрока |
| `threat.flee_hp` | float | доля hp, ниже которой отступает (`0` — дерётся до конца) |

### Где водится

| поле | тип | смысл |
|---|---|---|
| `habitat.biomes` | map id→вес | id каталога в `assets/biomes`; вес — частота в этом биоме |
| `habitat.zones` | enum[] | `water`, `shore`, `meadow`, `woods`, `trail`, `plateau`, `farmyard`, `indoor` |
| `habitat.group` | min/max | сколько приходит за раз |

`indoor` — зона сверх словаря животных: любая проходимая клетка подземелья или
пещеры. Worldgen размечает зоны только на открытых картах, и врагам подземелий
разметки пока нет — до неё `indoor` означает «где угодно внутри».

**В каждом биоме обязаны водиться минимум три типа врагов** — это проверяет
тест, читая список биомов из `assets/biomes`, а не из кода. Ниже трёх биом
перестаёт читаться как место: игрок встречает там одно и то же и решает, что мир
пустой. Сейчас разброс 3–6 типов на биом, в среднем 4.5:

| биом | типы |
|---|---|
| cave | goblin, golem, mushroom, rat, slime |
| cave_glowing | beholder, imp, mushroom, plant |
| cursed_area | demon, imp, lich, vampire |
| dead_island | ghost, lich, skeleton, zombie |
| desert | gnoll, lizardman, orc, skeleton |
| dungeon_1 | goblin, orc, rat, skeleton, slime, zombie |
| dungeon_2 | beholder, ghost, golem, skeleton, vampire |
| dungeon_3 | beholder, demon, imp, lich, vampire |
| farm | goblin, rat, zombie |
| fishing-docks | lizardman, rat, slime, zombie |
| flying_islands | beholder, ghost, golem, imp |
| forest | ent, gnoll, goblin, mushroom, orc, plant |
| glades | ent, gnoll, mushroom, plant |
| rocky | gnoll, goblin, golem, orc |
| ruined_tample | demon, ghost, golem, lich, skeleton, vampire |
| sewer | lizardman, rat, slime, zombie |
| swamp | ent, lizardman, mushroom, plant, slime |
| winterland | ghost, gnoll, skeleton, vampire |

Летающие острова достались тем, кто летает или охраняет руины (`beholder`,
`ghost`, `golem`, `imp`); ферму — тем, кто приходит из-за забора ночью
(`goblin`, `rat`, `zombie`); зимнюю землю — нежити и гноллам. Новый биом обязан
сразу обзавестись населением, иначе тест упадёт.

Зоны при этом должны сходиться с биомом: если тип поселили на ферму, у него
обязана быть зона `farmyard`, иначе спавнер не найдёт ему места на карте. То же
с открытыми биомами — одного `indoor` там мало.

### Что даёт

| поле | тип | смысл |
|---|---|---|
| `drops` | []{id,min,max,chance} | таблица выпадения (одна на тип) |
| `tiers.*.drop_rolls` | int | сколько раз таблица разыгрывается у этого тира |
| `tiers.*.xp` | int | опыт за убийство |

Дроп записан на типе, а не на тире: падает с крысы всегда одно и то же, разница
только в том, сколько раз кинуть кости.

---

## 3. Поля тира

| поле | тип | смысл |
|---|---|---|
| `title.ru` / `.en` | string | имя именно этой силы (`Скелет` → `Костяной рыцарь`) |
| `hp`, `damage` | int | здоровье и урон |
| `speed.walk` / `.run` | float | px в секунду; бег не может быть медленнее шага |
| `xp`, `drop_rolls` | int | см. выше |
| `element` | enum | только у слизней: цвет == стихия |

Стихия варианта берётся с тира, а при пустом поле — из `power.element` типа
(`Tier.Elem()`). Иначе лавовый слизень числился бы просто «рубящим».

---

## 4. `power` — украденная сила

Главное отличие от таблицы животных. `power` описывает, **что игрок получает,
убив этого моба**: возможность бить его ударом, оставаясь собой.

Работает это потому, что у врагов атака нарисована послойно. В `<пак>/parts`
лежат тело, голова, оружие, тень — и отдельно эффект:

```
demon1_attack_fire.png     ← огонь без демона
vampires1_attack_magic.png ← магия без вампира
zombie1_attack_smoke.png   ← дым без зомби
orc1_attack_swing.png      ← след клинка без орка
```

Наследуется именно этот слой: он накладывается на замах героя, совмещаясь по
точкам опоры (`anchor` из манифеста). Герой рубит своим мечом — из-под удара
бьёт чужой огонь.

| поле | смысл |
|---|---|
| `layer` | смысловой суффикс файла в `parts/` |
| `element` | `fire`, `magic`, `smoke`, `spectral`, `slash` |
| `tint` | `#rrggbb` — в какой цвет перекрасить слой в руках героя |
| `steal_chance` | шанс, что убитый отдаст силу |
| `charges` | сколько ударов даётся за одну добычу |
| `attack` | формат `loadouts.*.attack` из [character.json](../character/character.md) — сила становится альтернативным ударом героя |
| `attack.hit_at` | кадр **слоя-эффекта**, на котором наносится урон |

### Почему рубящим силам нужен `tint`

Стихии видно сразу: огонь оранжевый, магия вампира золотая, дым зомби зелёный,
удар призрака — тёмный серп. А вот `attack_swing` у всех десяти рубящих —
**белый след клинка**, ровно такой же, какой у героя рисует его собственный меч.
Украденный удар в этом случае неотличим от обычного, и вся механика на экране
пропадает.

Поэтому у рубящих сил цвет обязателен (валидатор ругается на его отсутствие), и
задан он по семье владельца:

| семья | цвет | кто |
|---|---|---|
| растения | `#7ad34a` зелёный сок | энт, хищный цветок |
| грибы | `#d6de5a` жёлтые споры | грибник |
| звери | `#e2593c` кровь | гнолл, крыса |
| гуманоиды | `#ffbe4a` калёная сталь | гоблин, орк, ящер |
| нежить | `#9fe6d8` холодная кость | скелет |
| големы | `#caa05a` каменная пыль | голем |

Перекраска сохраняет яркость пикселя, а не умножает цвет на цвет: белый след
становится цветом силы, а тени остаются тенями (умножение увело бы их в грязь).

**И второе, без чего цвет не спасает: на время чужого удара собственный взмах
героя не рисуется.** У персонажа атака тоже разложена по слоям
(`sword_attack1_shadow` … `6_swing`), поэтому герой собирается из всех слоёв
**кроме** `swing`, а его место занимает украденный эффект. Иначе на экране два
росчерка спорят друг с другом, и цвет тонет в белом.

**Числа в `attack` не назначены на глаз, а замерены по самим слоям:**

- `hit_at` — кадр, где у слоя больше всего непрозрачных пикселей (пик вспышки);
- `reach` — расстояние от ног владельца до самого дальнего пикселя эффекта;
- `arc` — угловой разброс эффекта вокруг среднего направления.

`damage`, `swing_ticks`, `cooldown_ticks`, `charges` и `steal_chance` — уже
баланс: чем сильнее удар, тем реже падает и тем длиннее замах. Огонь демона (22
урона, вылет 54) падает с шансом 0.15, крысиный замах (9 урона) — с 0.5.

`arc` обрезан по 180°: у ската скелета и укуса цветка замер дал больше, но
удар за спину владельца — это не удар, а недоразумение.

**У слизней и слизневого босса `power` равен `null`.** Не потому, что забыли: в
их `parts` только тело и тень, отдельного слоя эффекта нет — отбирать нечего.

Имена файлов в `parts/` художник вёл не строго: у `goblin/t1` слой зовётся
`attack6_swing`, у `t2` и `t3` — `attack_swing`. Поиск (`mob.LayerFile`)
сравнивает имена без цифр и отсеивает варианты удара на ходу, поэтому в таблице
записан один смысловой суффикс на все тиры.

---

## 5. Поля боссов

Живут в отдельном файле, потому что у шестидесяти обычных записей они пустовали
бы.

| поле | смысл |
|---|---|
| `arena.unique` | больше одного на карте не появляется |
| `arena.persistent` | не снимается спавнером по удалению игрока — босс обязан дождаться того, кто от него убежал |
| `phases[]` | `at_hp` (порог здоровья), `attack` (каким клипом бьёт), `speed_scale` |

Фазы идут сверху вниз по убыванию `at_hp`, и клип каждой фазы обязан быть в
паке — это проверяет тест. `attack2` есть только у боссов, у рядовых врагов
такого клипа нет.

---

## 6. Что проверяется

`go test ./internal/mob` гоняет обе таблицы:

- **связность данных** — `Validate()`: ссылки, диапазоны, `hp > 0`, бег не
  медленнее шага, `arc` в пределах 0..180, фазы по убыванию;
- **сходимость с графикой** — у каждого варианта грузится пак, в нём есть
  обязательные клипы и все четыре направления, а `id` манифеста совпадает с
  ключом таблицы;
- **сила существует** — для каждого типа с `power` слой находится в `parts` у
  **каждого** тира, и `hit_at` не выходит за длину клипа атаки. Именно этот тест
  нашёл разнобой в именах у гоблина.

## 7. Откуда берётся графика

```bash
go run ./tools/assetnorm -assets <распакованное сырьё> -out <staging>
go run ./tools/spriteanchor -root assets/mobs
```

`assetnorm` режет сырые паки CraftPix (`<src>/PNG/<Вариант>/With_shadow/`) в наш
вид и пишет `manifest.json`; `spriteanchor` дописывает в него `bbox` и `anchor`
по непрозрачным пикселям. Порядок важен: второй дополняет то, что переписал
первый.

**Порядок направлений** (`directions` в манифесте) `assetnorm` по умолчанию
берёт общий — `down, up, left, right`, — но он **не у всех паков такой**: у
персонажа строки идут `down, left, right, up`. Для таких паков порядок задаётся
явно в `mapping.json` (`"directions": [...]`), иначе герой в игре ходит вверх
боком. Все паки мобов проверены отражением рядов: у них порядок общий.
